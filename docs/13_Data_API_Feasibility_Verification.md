# 실제 데이터·API 구현 가능성 검증

> 역사·검증 근거: 이 문서는 2026-09-09~10에 수행한 원본 검증을 보존한다. 이후 서울시 확장 릴리스와 소진공 운영 스냅샷이 적재되었다. 현재 ACTIVE 릴리스와 구현 가능 범위는 [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)를 따른다.

원본 입수·공고 확인: 2026-09-09. 연도별 열 매핑 재검증 및 문서 작성: 2026-09-10.

## 1. 결론

**공공파일을 적재해 상권을 조회하고 사용자 가정으로 재무계획을 계산하는 MVP는 구현을 진행할 근거를 확보했다. 그러나 현재 API만 연결하면 모든 상권의 매출 분석과 예비 창업자 대상 대출 추천이 완성된다는 결론은 성립하지 않는다.**

이번 검증은 공식 파일의 실제 다운로드, CSV·DBF 파싱, 키 중복·누락 검사, 8개 분기 결합, 지원사업 원문 표본 확인이다. 인증키를 이용한 서울시·기업마당 API 호출, 신규 앱·DB 적재·상환 엔진·로그인·배포 테스트는 수행하지 않았다. 다운로드 성공을 API 운영 검증으로 간주하지 않는다.

## 2. 실제 내려받아 검사한 자료

| 추정매출-상권 | 2025년 | 85,732 | 55 | ZIP 안 CP949 CSV |

5개 파일 모두 공식 다운로드에서 HTTP 200으로 확보했다. 영역 파일은 CSV가 아니지만 DBF에 상권·자치구 코드와 명칭이 있어 지도 서버 없이 선택 목록을 만들 수 있다. 좌표·폴리곤의 정확성과 경계의 시점 일치까지 검증한 것은 아니다.

원천: [추정매출](https://data.seoul.go.kr/dataList/OA-15572/S/1/datasetView.do), [점포](https://data.seoul.go.kr/dataList/OA-15577/S/1/datasetView.do), [영역](https://data.seoul.go.kr/dataList/OA-15560/S/1/datasetView.do).

### 결합 결과

- 결합 키: 기준 연분기 + 상권 구분 코드 + 상권 코드 + 서비스 업종 코드.
- 2024~2025년 매출 **172,911행 전부** 점포 자료와 일대일로 결합됐다.
- 매출의 상권 코드도 영역 자료와 모두 결합됐다.
- 매출·점포 8개 분기의 결합 키 중복 및 누락은 각각 0건이다.
- 점포에는 있지만 매출에는 없는 조합은 **438,753행**이다. 이는 누락된 매출을 0원으로 채워도 된다는 뜻이 아니다. 미제공 원인은 이번 검사로 확정하지 않았다.
- 커피·음료 매출이 한 번 이상 관측된 상권은 1,127개, 8개 분기가 모두 존재하는 상권은 **1,022개**다.

2024~2025년의 8개 분기를 확보했다는 결과다. 2026년 최신 자료나 모든 상권의 연속 시계열을 검증했다는 의미는 아니다.

## 3. 구현할 때 반드시 반영할 발견 사항

### 열 이름은 파일별로 다르다

매출은 한글 열 이름이다. 점포는 2024년 한글, 2025년 영문 열 이름이다. 재검사에서 동일한 스키마를 가정하는 검증이 실제로 실패했으며, 2024년 한글 열을 명시적으로 대응시킨 뒤 재실행했다. 열 순서만 보고 읽지 말고 지원하는 헤더 목록을 검사하고 변환해야 한다.

### 이름 대신 코드로 결합한다

상권 코드 3110024는 매출·점포에서 ‘혜화동주민센터’, 영역에서 ‘혜회동주민센터’로 나타난다. 2025년 매출 32행·점포 156행에 걸친 동일 상권의 명칭 차이다. 원본 명칭을 보존하고 표시 명칭의 우선순위를 정해야 한다.

### 점포 수를 잘못 사용하기 쉽다

전체 611,664행에서 `stor_co + frc_stor_co = similr_induty_stor_co` 관계가 성립했다. 공식 점포 설명도 전체 점포를 일반 점포와 프랜차이즈의 합으로 안내한다. 따라서 `stor_co` 하나를 전체 점포라고 표시하지 않는다. 다만 이 일치 관계만으로 매출 추정 모집단과 점포 수의 분모가 같다고 증명되지는 않는다. **점포당 예상매출 계산은 보류한다.**

### 매출의 시간 단위는 추가 확정이 필요하다

CSV의 기간 열은 분기인데 금액 열은 `당월_매출_금액`이다. 데이터셋 FAQ에는 분기 매출이라는 표현이 있고, 서울시의 다른 공식 설명자료 8쪽은 해당 값을 분기 월평균으로 설명하며 연간 합계에 3을 곱한다. 후자의 자료는 다른 상권 사례이며 2026년 7월 제공 기준 변경 이전 자료여서, 이번 다운로드 파일의 모든 행에 그대로 적용한다고 확정할 수 없다. [데이터셋 FAQ](https://data.seoul.go.kr/dataList/OA-15572/F/1/datasetView.do), [서울시 설명자료](https://culture.seoul.go.kr/culture/cmmn/file/fileDown.do?atchFileId=af365d87d23c4c5b8411d3ba236292f6&bbsId=&fileSn=2&menuNo=200051).

현재는 원값·기준 분기를 보존한다. 공급기관의 해당 릴리스 정의가 확정될 때까지 월·연 환산값과 사용자 월매출 자동 입력을 제공하지 않는다. 코드가 연결됐다는 이유로 공간 기준의 역사적 동등성도 단정하지 않는다.

### 실제 결합 사례

입력: 성동구(11200) → 성수1가1동주민센터(3110127, 골목상권 A) → 커피·음료(CS100010).

| 기준 분기 | 원본 `당월_매출_금액`(원) | `stor_co` | `similr_induty_stor_co` | 개업 수 | 폐업 수 |
|---|---:|---:|---:|---:|---:|
| 2024년 4분기 | 229,353,124 | 10 | 13 | 0 | 1 |
| 2025년 1분기 | 183,367,983 | 10 | 13 | 0 | 0 |
| 2025년 2분기 | 220,443,234 | 9 | 12 | 0 | 1 |
| 2025년 3분기 | 255,984,520 | 9 | 12 | 0 | 0 |

이는 공개 집계 원값이며 특정 점포나 신규 창업자의 예상매출이 아니다. 전체 8개 분기 표본은 검증 JSON에 보존했다.

예비창업패키지는 실제 첨부 PDF를 내려받아 텍스트를 추출하고 신청자격 등 주요 페이지를 이미지로 확인했다. 나머지는 공식 웹 상세를 검토했다. 이 표는 조건 구조화 가능성의 표본이며, 전체 공고의 모든 예외·증빙을 검수한 운영용 상품 목록은 아니다.

**검토한 4건으로 현재 신청 가능한 예비 창업자용 대출 5~10개를 확보했다고 말할 수 없다.** 최신 공식 운영자금 안내와 과거 창업자금 검색 결과도 동일 상품처럼 합치지 않는다.

### API만으로 부족한 정보

기업마당 API 명세에는 공고명·기간·대상·본문·첨부·링크가 있지만 모든 상품의 금리, 거치기간, 상환방식, 자금 용도, 예외 조건을 통일된 금융 스키마로 보장하지 않는다. 인증키 `crtfcKey`도 필수다. 이번에는 해당 인증키로 응답을 받아 검증하지 않았다. [기업마당 API 명세](https://www.bizinfo.go.kr/apiDetail.do?id=bizinfoApi).

초기에는 공식 공고를 검수한 JSON으로 관리한다. `지원유형`, `신청기간`, `사업단계`, `조건 기준일`, `미확인 조건`, `공식 URL`, `확인일`을 저장한다. 상세 금융 조건이 확인된 대출만 상품 기반 상환 계산에 연결한다. 지원금·공간 지원은 정보로 제공하고 조달액에 자동 반영하지 않는다.

## 5. 구현 방향에 반영할 결정

1. 외부 API 추가보다 먼저 현재 파일용 적재기를 만든다. CP949 CSV와 UTF-8 DBF를 읽고 명시적 열 매핑, 중복 검사, 출처·checksum 보존을 수행한다.
2. 상권 목록은 영역 속성으로 만들고 가용 업종·분기를 함께 조회한다. 매출 미제공은 null 상태로 보존한다.
3. 재무계획은 사용자 입력을 기준으로 별도 계산한다. 상권 매출을 개인 예상매출로 자동 대입하지 않는다.
4. 지원사업은 조건 검토 후보로 제공한다. 후보 0건에서도 무차입 또는 사용자 가정 대출 계산을 계속할 수 있게 한다.
5. 기존 계획의 Next.js 단일 앱·PostgreSQL 단일 DB 구조를 유지한다. 지도 서버, 자동 공고 해석 AI, 별도 분석 DB를 추가할 근거는 이번 검증에서 발견하지 못했다.

원자료 결합을 이용한 개발은 시작할 수 있다. 다만 매출 환산·점포당 매출의 공개 제공, 실제 대출 조건을 이용한 자동 추천은 각각 원천 정의와 상품 검수를 완료한 뒤 활성화해야 한다.

## 6. 재현 자료와 남은 검증

- [검사 스크립트](verification/verify_market.py): pandas 기반 읽기·결합 검사. 운영 적재기가 아니다.
- [검사 결과](verification/market-verification.json): 행 수, 중복·누락, 결합 범위, 실제 표본, 원본 SHA-256, 다운로드 파라미터.
- 원본 파일 보관 위치: 저장소 루트의 `data/raw/`(Git 제외). 준비 방법은 [검증 도구 안내](verification/README.md)를 따른다.

재실행 예시:

```powershell
python docs/verification/verify_market.py --source-dir data/raw
```

Python과 pandas가 필요하다. 검사는 원본 ZIP을 수정하지 않고 지정 폴더의 결과 JSON을 갱신한다. 재다운로드 때 파일 내용·목록이 달라질 수 있으므로 checksum과 제공 기준도 다시 확인한다.

남은 항목: 해당 릴리스 매출 시간 단위·모집단 확정, 최신 2026 자료 검증, 실제 운영용 상품 검수, 인증 API 응답·쿼터·오류 처리, DB 적재·권한·계산 엔진·전체 사용자 흐름·배포 테스트. 따라서 이번 결과는 **데이터 기반 구현 가능성의 부분 검증 완료**이며 출시 준비 완료는 아니다.
