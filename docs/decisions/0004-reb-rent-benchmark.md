# ADR 0004: 한국부동산원 임대동향조사로 임대료 참고값 제공

- Status: Accepted
- Date: 2026-09-24
- Owners: jhjh0512
- Related issue/PR:
- Supersedes: 없음

## Context

사업 조건에는 자치구·면적·층·상가 유형이 있지만, 임대료 자료가 없어 `/api/rent-benchmarks`는 503을 반환했다. 사용자는 월 임대료를 근거 없이 직접 입력해야 했다.

한국부동산원 상업용부동산 임대동향조사(국가승인통계 408001)는 R-ONE Open API로 제공된다.

- **표:** 2024년 3분기 이후 조사 체계의 지역별 임대료, 층별 임대료, 공실률. 상가 유형은 소규모·중대형·집합으로 사업 조건과 같다.
- **서울 범위:** 서울 전체, 권역 4개(도심·강남·영등포신촌·기타), 조사 상권 72곳. 2026-09-24 기준으로 2024년 3분기~2026년 2분기가 있다.
- **정의:** 임대료 = (보증금 × 전환율 ÷ 12 + 월 임대료) ÷ 임대 면적(전용+공용). ㎡당 월 시장임대료이며, 관리비는 포함하지 않는다. 지역별 상가 임대료는 1층 기준이고, 1층이 없으면 2층을 쓴다. 단위는 천원/㎡다.
- **지역 단위:** 조사 상권은 역·거리 이름이다. 원본에 자치구가 없고, 서울시 상권(1,650곳)과도 단위가 다르다.
- **지역 ID:** 같은 지역이라도 표마다 ID가 다르다. 예를 들어 남대문은 중대형 표에서 520005, 집합 표에서 520004다.

## Decision

1. **적재:** 운영자 명령 `rent:load`가 표 9개(상가 유형 3종 × 지역별 임대료·층별 임대료·공실률)를 받는다. 인증키는 `app/.env.local`의 `REB_API_KEY`에 둔다. 서울 행만 `rent_benchmark_releases`·`rent_benchmark_observations`에 저장하고, 원본 값·단위와 빈 값(NULL)을 그대로 보존한다.
2. **검증:**
   - 표 ID마다 표 목록의 이름과 대조한다.
   - 받은 행 수가 전체 건수와 같아야 한다.
   - 항목·단위·분기·층을 해석할 수 없는 행, 음수, 100%를 넘는 공실률은 거부한다.
   - 9개 표의 서울 분기가 같고 연속이어야 한다.
   - 관측 키가 중복되지 않아야 한다.
   - 상가 유형마다 세 표의 서울 지역이 같아야 한다.
3. **출처:** 표마다 행 순서와 무관한 내용 해시를 남긴다. 릴리스 키는 저장한 관측값의 내용 해시로 만들므로, 같은 내용을 다시 받으면 `ALREADY_ACTIVE`다. 지역은 경로(`서울>기타>뚝섬`)로 잇는다.
4. **자치구 연결:** 조사 상권이 가리키는 위치를 보고 운영자가 자치구와 잇는다(`regions.ts`). 경계에 걸친 상권은 걸친 자치구를 모두 적는다. 이 연결로는 "주변 조사 상권" 후보만 보여 주고, 어느 지역 값을 볼지는 사용자가 고른다. 연결 버전은 API 응답에 싣는다.
5. **표시:**
   - API는 ㎡당 금액을 원 단위 정수 문자열(천원 × 1,000, 반올림)로 돌려준다. 원본 소수 값도 함께 싣는다.
   - 화면은 선택 층의 ㎡당 임대료에 사업 조건의 면적을 곱해 월 임대료 참고값을 보여 준다. 1평은 400/121㎡로 환산한다.
   - "2층 이상"은 2층 값으로 본다. 층 조사값이 없으면 다른 층으로 대체하지 않고 "자료 없음"으로 표시한다.
6. **재무계획과의 경계:** 참고값은 재무 입력에 자동으로 넣지 않고, 계산 결과에 저장하지 않는다. 계약 3번을 "상권·임대료 관측값"으로 넓힌다. 부동산원 값은 보증금 환산분을 포함하므로 사용자가 입력한 월세와 차이가 날 수 있다고 함께 표시한다.

## Alternatives considered

- **서울시 상권에 부동산원 값 배정:** 조사 상권 경계 파일로 공간 결합해야 하고, 두 체계의 단위가 달라 정밀도를 과장한다. 기각한다.
- **자치구 평균 계산:** 원본에 없는 집계를 새로 만든다. 기각한다.
- **공공데이터포털 파일:** 분기마다 수동으로 내려받아야 하고, 이미 Open API 키가 있다. 기각한다.
- **2022년~2024년 2분기 표 병합:** 조사 체계가 바뀐 전후 값을 한 추이로 이으면 오해를 부른다. 이번에는 2024년 3분기 이후만 쓴다.

## Consequences

- 장점: 사용자가 층·상가 유형·면적에 맞는 공식 임대료 수준을 보고 월 임대료 가정을 세운다.
- 비용·위험:
  - 적재 한 번에 약 30초, 요청 약 90회가 든다.
  - 부동산원이 조사 상권을 추가하면 자치구 연결이 없는 상권이 생긴다. 적재는 계속되고, 연결되지 않은 상권 목록이 출력과 검증 요약에 남는다.
  - 표 ID나 이름이 바뀌면 적재가 멈춘다. `types.ts`의 표 정의를 고쳐야 한다.
- migration·호환성: 새 테이블 2개(`20260924010000_rent_benchmarks`). 기존 데이터는 바뀌지 않는다.

## Validation

- `app/src/features/rent-benchmark/rent-benchmark.test.ts`가 다음을 검증한다.
  - 환산(평·반올림·null)
  - 자치구 연결, 표 해석과 거부 규칙
  - 페이지 수신, 키 가림, 순서와 무관한 릴리스 키
  - DB 활성화와 재적재
- `app/e2e/rent-benchmark.spec.ts`(데스크톱·모바일): 사업 조건 입력 → 주변 조사 상권 기본 선택 → 월 참고값 계산 → 지역 변경 → 빈 층 표시.
- 2026-09-24 실제 적재 결과: `reb-rent-seoul-2024q3-2026q2-d1fcfccdc683`, 관측값 11,056건, 검사 5개 통과, 조사 상권 72곳 모두 자치구 연결.
