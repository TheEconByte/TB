# ADR 0003: 서울시 상권 데이터를 Open API로 적재

- Status: Accepted
- Date: 2026-09-23
- Owners: jhjh0512
- Related issue/PR: #9
- Supersedes: 없음

## Context

지금까지 `market:load`는 2026-09-09에 내려받은 ZIP 원본 5개(`data/raw/`)를 기록된 파일 크기·SHA-256으로 검증해 적재했다. 그래서 두 가지 문제가 있었다.

- **원본 공유 부담:** 새 PC는 같은 파일을 기존 보유자에게 받아야 했다.
- **다시 받기 어려움:** 서울시가 2024년부터 공간 단위를 표준단위구역으로 바꿨고, 2026-07-03부터는 2021년 이후 자료만 제공한다. 그래서 새로 내려받은 파일은 기록과 달라질 가능성이 컸다.

서울 열린데이터광장 Open API는 같은 데이터셋을 제공한다.
- 서비스: 영역 `TbgisTrdarRelm`, 추정매출 `VwsmTrdarSelngQq`, 점포 `VwsmTrdarStorQq`
- 분기별로 받을 수 있고, 2026년 2분기까지 있다.

2026-09-23에 API를 기존 파일 적재본과 대조한 결과는 다음과 같다.
- **영역:** 1,650건 모두 코드·자치구가 같다. 이름 2건만 표기가 다르다(혜회동/혜화동, KT&G/KTNG).
- **행 수:** 2024~2025년 8개 분기가 매출 172,911행, 점포 611,664행으로 파일과 같다.
- **값:** 2025년 4분기 지원 업종 2,475행의 금액·건수가 모두 같다.

## Decision

1. **기본 원본을 Open API로 바꾼다.** 인증키는 `app/.env.local`의 `SEOUL_OPEN_API_KEY`에 둔다.
2. **기본 범위:** 2024년 1분기부터 매출·점포가 모두 있는 최신 분기까지다. `--from`·`--to`로 바꿀 수 있다.
3. **파일 적재는 옵션으로 남긴다.** `--source-dir`로 2026-09-09 검증본을 재현하고, 파일 대조 테스트도 유지한다.
4. **검증:**
   - 분기마다 받은 행 수가 API 전체 건수와 같아야 한다.
   - 받는 도중 전체 건수가 바뀌거나, 요청한 분기가 비어 있거나, 응답 필드 구성이 기록과 다르면 적재하지 않는다.
   - 코드·분기·키·중복·음수·점포 수 항등식·영역 결합은 파일과 같은 검증을 쓴다.
5. **출처:**
   - 파일 checksum 대신, 서비스·분기마다 행 순서와 무관한 내용 해시를 남긴다. 필드 순서를 고정한 행 문자열을 정렬해 SHA-256을 구한다.
   - 릴리스 키는 이 해시로 만든다. 그래서 같은 내용을 다시 받으면 `ALREADY_ACTIVE`다.
   - 받은 시각을 `retrievedAt`에 기록한다.

## Alternatives considered

- **파일만 유지:** 새 PC 준비가 원본 공유에 묶이고, 최신 분기를 받을 수 없다. 기각한다.
- **파일 경로 삭제:** 검증본 재현과 기존 파일 대조 테스트를 잃는다. 기각한다.

## Consequences

- 장점: 인증키만 있으면 누구나 같은 데이터를 받는다. 최신 분기까지 쓴다.
- 비용·위험:
  - 적재 한 번에 약 2분, 약 1,000회 요청이 든다.
  - 서울시가 과거 분기를 고치면 내용 해시가 바뀌어 새 릴리스가 된다.
  - 로그와 오류는 인증키를 가린다.
- migration·호환성: DB 변경은 없다. 출처는 기존 JSON 필드(`files`, `validationSummary.sourceQuarters`)에 담는다.

## Validation

- `app/src/features/market/seoul-api.test.ts`가 다음을 검증한다.
  - 페이지 수신, 전체 건수 대조, 재시도, 인증키 가림
  - 행 순서와 무관한 릴리스 키, 빈 분기 거부
  - DB 활성화와 재적재 시 중복 없음
- 2026-09-23 실제 적재 결과: `seoul-market-2024q1-2026q2-a8468e32081c`, 검사 4개 통과.
