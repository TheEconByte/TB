# ADR 0009: 자금 공고의 조건은 공고 본문에서 AI로 읽고, 사용자 입력과 맞춰 보여 준다

- Status: Accepted
- Date: 2026-11-02
- Owners: jhjh0512
- Related issue/PR: #44, #45, #46, #48, [ADR 0006](0006-funding-discovery-automation.md), [ADR 0007](0007-semas-ols-status-and-fund-identity.md), [ADR 0008](0008-market-survival-score.md)
- Supersedes: ADR 0006의 일부, ADR 0008의 자금 조건 업종 채우기. 범위는 [6절](#6-바뀌는-기존-결정과-규칙)에 있다.

## Context

자금 기능이 할 일은 사용자 입력과 수집한 공고를 이어서 조건에 맞는 정책자금·지원사업을 보여 주는 것이다.

### 수집 데이터의 구조화된 항목에는 조건이 거의 없다

| 출처 | 갈래 | 구조화된 항목 |
|---|---|---|
| 기업마당 API | 지원사업(일부 정책자금) | 공고명, 기관, 신청기간, 지원대상 태그(`trgetNm`), 지원분야(금융·기술·창업 …), 공고 URL (`app/src/features/funding/sources/bizinfo.ts:69-79`) |
| 소진공 정책자금 사이트 | 정책자금 | 자금명, 신청요건 문장, 대출기간·한도·금리 문장, 공통 자격, 접수중 표시, 공지 접수기간 (`app/src/features/funding/sources/semas-ols.ts:42-91`) |

연령, 업력, 대상 지역(자치구), 예비 창업자 가능 여부, 제외 업종, 청년·여성 같은 대상 한정은 항목에 없다. 이런 조건은 **공고 본문과 첨부**에 있다.

### 그래서 지금 구현은 조건을 추측하고, 추측을 관리하느라 복잡해졌다

- 기업마당 지역은 공고명 `[서울]` 표시와 소관기관에서 추측한다(`bizinfo.ts:160-191`). 2026-10-31~11-02에 #45, #46으로 고쳤고 리뷰가 약 9라운드 돌았는데도 알려진 한계가 남았다(`docs/domains/funding.md:119`).
- 소진공은 "지역 제한 문장 없음 → 전국", "소상공인 → 사업자등록 이후"로 기록한다(`semas-ols.ts:631-642,696-697`).
- 추측에 공식 근거를 붙여 판정하고(`eligibility.ts:178-193`), 그 추측을 막으려고 검수자·스위치·탐색 전용 출처 같은 예외가 붙었다(`eligibility.ts:378-409`).
- 그런데도 지금 현재 후보는 0건이다. 사람 등록 5건은 검수자가 `UNASSIGNED`이고 자동 승격 스위치도 꺼져 있다(`app/catalog/funding/catalog.json:6,17-22`). 상환 계산 가능 상품도 0건이다(ADR 0006 첫 실행 기록).

### 본문은 구할 수 있다

- 기업마당 API는 공고 상세 URL과 공고문 PDF 경로(`printFlpthNm` 본문출력파일, `flpthNm` 첨부)를 준다. 지금 수집기는 이 필드를 읽지 않는다. 2026-11-02 기준 robots.txt는 상세 페이지와 파일 경로(`/cmm/fms/…`)를 막지 않는다.
- 소진공은 공지 상세 HTML을 이미 받는다. 지금은 접수기간·대상·제외 줄만 뽑고 나머지는 버린다.
- 서울시 육성자금은 조건이 HWP 첨부에만 있다. 기업마당 공고도 첨부가 HWP뿐인 경우가 많다.
- Claude API는 HWP를 파일로 받지 않지만, HWP·HWPX는 텍스트로 바꿀 수 있다. HWPX는 ZIP 안의 XML이고, HWP 5.0은 한컴이 형식 문서를 공개했으며 텍스트를 뽑는 오픈소스 라이브러리가 있다.

본문은 자유 문장이다. 규칙(정규식)으로 조건을 뽑으면 지역 규칙과 같은 문제가 반복된다. 그래서 AI로 읽는다. 지금 AGENTS.md §2와 ADR 0006 8절, PRODUCT.md 범위 밖 목록(`docs/PRODUCT.md:38`)이 AI 공고 해석을 막고 있어 이 ADR이 필요하다.

## Decision

### 1. 갈래

- **정책자금:** 소진공 수집 자금 전부, 기업마당 중 지원분야가 "금융"인 공고, 사람이 등록한 대출·보증 상품.
- **지원사업:** 기업마당의 나머지 공고, 사람이 등록한 지원금·공간·프로그램 상품.
- 갈래는 출처와 출처의 지원분야 항목으로만 정한다. 분류 규칙을 따로 두지 않는다.

### 2. 수집: 목록에 본문을 더한다

- **기업마당:** 지금처럼 목록을 받는다. 신청이 끝나지 않았고 지원대상 태그에 소상공인·창업벤처가 있는 공고만, 본문출력파일과 첨부 중 PDF·HWP·HWPX를 받아 텍스트로 바꿔 합친다. 지역으로는 거르지 않는다.
- **소진공:** 공지 상세 본문 전체와 정책자금 표의 자금 행을 텍스트로 남긴다.
- **서울시 육성자금:** 기업마당 "금융" 공고의 HWP 첨부로 읽는다. 기업마당에 공고가 없거나 변환에 실패하면 운영자가 `catalog.json`에 등록한다.
- **읽지 않는 것:** 텍스트를 뽑지 못한 파일(스캔본 PDF, 손상된 HWP 등)과 그 밖의 형식(이미지, 엑셀 등). 읽을 파일이 하나도 없는 공고는 조건을 "읽지 못함"으로 둔다.
- 본문 텍스트, 원 URL, checksum, 받은 시각을 DB에 저장한다(§3의 10번). 원 파일은 저장하지 않는다.
- 수집 규칙(robots·약관 확인, 요청 간격, 403·429에서 멈춤), 출처 실패 시 직전 데이터 유지, `PENDING → ACTIVE`는 [ADR 0006](0006-funding-discovery-automation.md) 그대로다.

### 3. AI 추출

- **언제:** 운영자 명령 안에서만 부른다. 웹 요청 중에는 부르지 않는다(AGENTS.md §2). 처음에는 적재 명령(`funding:sync`)뿐이었고, 2026-11-04에 프롬프트를 바꾸기 전후에 재는 평가 명령(`eval:funding-conditions`)이 같은 추출 코드를 부르도록 더했다.
- **무엇을:** 정해진 JSON 스키마(구조화 출력)로 읽는다. 항목마다 값과 근거가 된 원문 인용을 함께 받는다.

| 항목 | 값 |
|---|---|
| 신청 대상 단계 | 예비 창업자만 / 사업자만 / 둘 다(제한 없음 포함) / 언급 없음 |
| 업력 | 최소·최대 n년(최대가 미만인지 이하인지 함께), 또는 언급 없음 |
| 연령 | 최소·최대 나이(최대가 미만인지 이하인지 함께), 또는 언급 없음 |
| 지역 | 전국 / 시·도 목록 / 서울 자치구 목록, 제외 지역 목록 / 언급 없음 |
| 음식점·카페 제외 | 제외됨(음식점·카페를 제외 업종으로 밝힘, 또는 지원 업종 목록에 없음) / 제외 아님(업종 제한이 명시돼 있고 음식점이 빠지지 않음, 또는 업종 제한이 없다고 밝힘) / 언급 없음 |
| 대상 한정 | 청년·여성·장애인·재창업·피해 소상공인 등, 또는 없음 |
| 신청기간 | 시작일·종료일, 또는 문장 |
| 지원 유형 | 대출 / 보증 / 지원금 / 공간 / 교육·프로그램 / 기타 |

- 업력 하한, 미만·이하 구분, 제외 지역, 신청 단계와 음식점·카페 제외의 "제한 없음" 표기는 구현 리뷰에서 "업력 3년 이상" 같은 공고가 "제한 없음"으로 기록되는 것을 보고 더했다(사용자 결정, 2026-11-03).
- 음식점·카페 제외는 유흥주점 등만 빼는 공고를 "제외 아님", 지원 업종 목록에 음식점·카페가 없는 공고를 제외 업종 문장과 상관없이 "제외됨"으로 읽는다. 맞춰 보기 구현 리뷰에서 "유흥주점업 제외"가 음식점 제외로, "제조업만 지원 + 유흥업 제외"가 제외 아님으로 읽힐 수 있음을 보고 프롬프트에 밝혔다(사용자 결정, 2026-11-03).
- **"언급 없음"과 "제한 없음"을 구분한다.** 본문에 연령 조건이 없으면 "제한 없음"이 아니라 "언급 없음"이다(§3의 2번).
- **인용 검증:** 각 값의 인용문이 저장한 본문 텍스트에 그대로 있어야 한다. 없으면 그 값은 버리고 "읽지 못함"으로 둔다. AI가 지어낸 값을 기계적으로 걸러 내는 장치다.
  - 상품 이름(공고 제목이나 자금 이름)도 원문으로 본다. 제목도 공고의 일부라 조건을 밝히기 때문이다. 기업마당 지자체 공고는 지역을 제목의 [시·도] 표시로만 밝히는 일이 많은데, 본문만 대조하면 그 지역이 버려졌다. 제목과 본문은 따로 대조해, 둘을 이어 붙인 인용은 받지 않는다(사용자 결정, 2026-11-12).
- **다시 부르지 않는다:** 본문 checksum, 프롬프트 버전, 모델이 같으면 저장한 결과를 쓴다. 결과에는 모델 id, 프롬프트 버전, 본문 checksum, 추출 시각을 남긴다.
- **실패:** AI 호출이 실패한 공고는 "읽지 못함"으로 두고 다음 동기화에서 다시 시도한다. 출처 동기화 실패로 보지 않는다.
- **모델과 키:** Claude API(`@anthropic-ai/sdk`)의 `claude-haiku-5-5`를 쓴다(사용자 결정, 2026-11-02). 운영자가 결과를 보고 오독이 많으면 모델이나 프롬프트를 바꾼다. 키(`ANTHROPIC_API_KEY`)는 `app/.env.local`과 운영 비밀값에만 두고 로그에 남기지 않는다.
- **사람 등록 상품:** `catalog.json`에 사람이 적은 조건이 있으면 AI 값 대신 그것을 쓰고 "운영자 확인"으로 표시한다.

### 4. 사용자 입력과 화면

- **입력:** 연결할 데이터가 있는 것만 받는다.
  - 사업자등록 여부(예비 창업자 / 사업자). 사업자면 개업 연월
  - 자치구: 자금 조건의 자치구를 쓰고, 비어 있으면 계획의 사업 프로필(`businessProfileJson.districtCode`)을 쓴다. 상권에서 넘어온 경우 [ADR 0008](0008-market-survival-score.md)대로 상권의 자치구가 채워진다
  - 나이: 선택. 청년 한정 공고도 나이로 맞춰 본다
  - 대상 한정: 선택. 여성, 장애인, 재창업 중 해당하는 것을 고른다. 공고가 특정 대상으로 한정돼 있는데 사용자가 어느 것에도 해당하지 않으면 안 맞음, 입력하지 않았으면 확인 필요다
    - 재난 피해 소상공인으로만 한정한 공고는 범위에서 뺀다. 그래서 피해 소상공인은 입력받지 않고 해당하지 않는 것으로 보아, 그런 공고는 안 맞아 보임이 된다. 사용자가 "피해 소상공인"이라고 답해도 특정 재난의 피해자인지 맞춰 볼 수 없다는 구현 리뷰를 보고 정했다(사용자 결정, 2026-11-03)
  - 업종: 받지 않는다. 제품이 음식점·카페 전용이라 "음식점·카페 제외" 항목으로만 본다
  - 용도: 받지 않는다(연결할 데이터가 없다)
- **맞춰 보기:** 공고의 항목마다 맞음 / 안 맞음 / 확인 필요(언급 없음·읽지 못함·사용자 미입력)로 본다. 접수가 끝났으면(신청 종료일 경과, 소진공 마감 표시) 마감이다. 마감은 출처·운영자의 접수 상태와 종료일로만 정한다. AI가 읽은 값으로는 공고를 마감으로 숨기지 않는다(조건이 안 맞는 공고를 목록에서 빼는 것은 아래 2026-11-13 결정). AI가 읽은 종료일이 지났으면 마감으로 숨기지 않고 접수 여부 미확인으로 둔다(사용자 결정, 2026-11-03. 리뷰 두 번에서 AI 값으로 숨기는 규칙마다 예외가 생기는 것을 보고 정했다).
- **그룹은 조건으로만 나눈다(사용자 결정, 2026-11-13).** 마감이 아닌 공고의 그룹은 여섯 항목의 판정으로만 정하고, 접수 상태는 그룹과 따로 카드에 보여 준다.
  - 2026-11-03에는 맞아 보임에 "여섯 항목이 모두 맞음"과 "출처에서 접수 중으로 확인"을 함께 요구했다. 2026-11-13 릴리스(공고 290건)를 세 가지 입력(입력 없음, 예비 창업자·마포구·32세, 2025년 3월 개업 사업자·강남구·45세)으로 맞춰 보니 맞아 보임이 모두 0건이었다. 나이를 말하지 않는 공고가 238건, 업력을 말하지 않는 공고가 167건이고, 출처의 접수 상태가 접수 중인 공고는 73건뿐이다(기업마당 199건은 "예산 소진시까지"처럼 날짜 없는 표기라 접수 상태를 알 수 없다). 그래서 걸리는 조건이 없는 공고와 조건을 읽지 못한 공고가 확인 필요 한 그룹에 섞였다.
  - 접수 상태는 셋 중 하나다. 접수 중 확인: 출처·운영자의 접수 상태가 접수 중이고, 자동 상품이면 출처가 최신이며(3일, ADR 0006), AI가 읽은 종료일이 지나지 않았다. 접수 여부 미확인: 그 밖이며 이유를 함께 보여 준다. 마감: 위 맞춰 보기의 마감.
  - 그룹 안에서는 접수 중으로 확인한 공고를 먼저 놓는다.
  - 소진공 수집기의 제외 신호(ADR 0006 4절 3번)와 3일 최신성은 접수 중 확인이 되지 않게 할 뿐 그룹을 바꾸지 않는다. 음식점·카페 제외 여부는 AI가 읽은 항목으로 맞춰 본다.
  - 바꾼 뒤에도 같은 릴리스와 같은 세 입력에서 맞아 보임은 0건이다. 걸리는 조건 안 보임은 입력 없음 0건, 예비 창업자 2건, 사업자 13건이다. 그 13건 중 5건은 지역을 제목의 [시·도] 표시나 기관 이름으로만 밝힌 지방 공고로, AI가 지역을 언급 없음으로 읽어 올라왔다. 이 그룹은 언급 없음의 정확도에 기대므로, 조건 추출 평가가 정답과 그룹이 달라진 회차를 따로 잰다(`docs/domains/funding.md`의 조건 추출 평가).
  - 제목의 [시·도] 표시로 내린다(사용자 결정, 2026-11-13). 기업마당 공고의 지역을 AI가 언급 없음으로 읽었는데 제목 맨 앞에 서울도 전국도 아닌 `[..]` 표시가 있으면, 지역 항목의 확인 필요 이유를 언급 없음이 아니라 제목 표시로 둔다. 그래서 그 공고는 걸리는 조건 안 보임이 아니라 확인 필요에 남는다. 위 13건 중 [충남]·[전남광주]·[부산] 3건이 이렇게 내려가 10건이 된다(릴리스 전체에서는 6건의 이유가 바뀐다).
    - 내리는 데만 쓴다. 표시로 지역 값을 정하지 않고, 안 맞음으로 만들지 않으며, 공고를 숨기지 않는다(§2·§7에서 없앤 제목 규칙을 되살리지 않는다). 같은 릴리스에 제목은 [대구]인데 본문은 대전 유성구인 공고가 있어 표시를 값으로 믿을 수 없다. AI가 지역을 읽었으면 표시는 보지 않는다.
    - 표시 없이 기관이나 시설 이름으로만 지역이 드러나는 공고(소담스퀘어 in 광주, 제주창조경제혁신센터)는 그대로 올라온다.
  - "언급 없음"은 여전히 맞음이 아니다(§3). 맞음이 아닌 항목이 언급 없음뿐인 공고를 따로 묶어 보여 줄 뿐이다.
- **조건이 안 맞는 공고는 목록에서 뺀다(사용자 결정, 2026-11-13).** 2026-11-03에는 AI가 잘못 읽을 수 있어 안 맞아 보이는 공고도 접어 두고 보여 주기로 했다. 그런데 사업자·강남구·45세 입력에서 290건 중 228건이 안 맞아 보임이라, 사용자가 볼 공고가 그 속에 묻힌다. 그래서 안 맞는 항목이 하나라도 있는 공고는 목록에서 뺀다.
  - 뺀 건수를 탭과 목록에 밝히고, 버튼으로 뺀 공고를 펼쳐 안 맞은 조건과 인용을 다시 볼 수 있게 한다. API 응답에서는 지우지 않는다. AI가 잘못 읽어 빠진 공고를 사용자가 되찾을 수 있어야 하기 때문이다.
  - 빼는 것은 안 맞음이 있는 공고뿐이다. 조건을 읽지 못했거나, 공고문에 언급이 없거나, 입력이 없어 맞춰 보지 못한 공고는 남긴다. 제목의 [시·도] 표시만으로는 빼지 않는다.
  - 마감은 그대로 출처·운영자 데이터로만 정하고 기본으로 숨긴다.
- **화면:** 정책자금·지원사업 탭마다 남은 공고를 한 목록으로 보여 준다. 목록 안의 순서는 맞아 보임, 걸리는 조건 안 보임, 확인 필요 순이고 그 안에서는 접수 중으로 확인한 공고가 먼저다. 그룹 제목으로 나누지 않는다. 그 아래에 조건에 안 맞아 뺀 공고와 마감 공고를 건수와 함께 두고, 버튼으로 펼친다.
- **카드:** 공고가 밝힌 조건만 값과 원문 인용으로 적고, 입력과 맞춰 본 결과(맞음·안 맞음·확인 필요)를 붙인다. AI가 읽지 못한 조건은 직접 확인할 조건으로 따로 적고, 공고문에서 찾지 못한 조건은 이름만 한 줄로 적는다(언급이 없다고 제한이 없다는 뜻이 아님을 함께 적는다). "AI가 공고문에서 읽은 내용입니다. 신청 전 원 공고를 확인하세요"와 원 공고 링크를 붙인다. "신청 가능", "승인"이라고 쓰지 않는다(PRODUCT.md 원칙 5).
- **정책자금 탭:** 계획의 부족자금을 자금의 한도 문장 옆에 참고로 보여 준다. 한도는 최대치이고 실제 금액은 심사로 정해진다고 함께 적는다.

### 5. 대출 가정 적용 기능을 없앤다

사용자 결정(2026-11-02). 운영자가 적은 조건이 있는 상품에만 남기는 안도 검토했지만, 쓰이지 않는 경로를 유지하는 비용이 더 크다고 보았다.

- AI가 읽은 금리·기간을 상환 계산에 넣지 않는다. 틀리면 상환액이 틀린다(§3의 1번).
- 지금 적용할 수 있는 상품이 0건이라(Context), 상품 조건을 계획에 옮기는 경로(`POST /api/plans/{id}/loan-assumption`)를 없앤다. 사용자는 지금처럼 대출 조건을 재무 계획에 직접 입력한다.
- 이미 저장된 `plans.loanAssumptionJson`·`plan_results.loanAssumptionJson`은 그대로 읽고 표시한다. 새로 쓰지 않는다(§3의 7번).

## Alternatives considered

- **공고명·항목 규칙을 계속 고침:** #45, #46에서 끝이 나지 않음을 확인했다.
- **판정 없이 목록과 필터만:** 가장 단순하지만, 조건이 본문에만 있어 사용자가 공고를 하나씩 열어 읽어야 한다.
- **본문 키워드 검색:** 판정이 없어 틀릴 일은 없지만 "청년 제외"도 "청년"으로 걸린다.
- **근거 종류를 나눠 기록하는 관측·주장 모델(이 ADR의 첫 초안):** 추측이 판정하는 것은 막지만 구조가 크다(새 테이블 여러 개, 자금 코드 대부분 재작성). 조건 데이터가 없는 문제는 그대로다.
- **사람이 모든 공고를 검수:** 기업마당 공고 수(하루 약 1,500건 중 대상 태그 공고만 해도 수십~수백 건)를 감당할 수 없다.

## Consequences

- **장점:**
  - 연령·업력·자치구·예비 창업자 가능 여부 같은 실제 조건으로 공고를 맞춰 볼 수 있다.
  - 지역 규칙, 검수 상태, 스위치 같은 예외 코드가 사라진다.
  - 판정 근거가 항상 원문 인용으로 보인다.
- **비용·위험:**
  - **AI 오독:** 인용 검증은 지어낸 인용을 막지만, 인용은 맞는데 해석이 틀리는 경우는 막지 못한다. 그래서 "맞아 보임"으로만 표시하고 원문 확인을 안내한다. 정해진 정확도 기준은 두지 않고, 운영자(jhjh0512)가 결과를 보고 오독이 많으면 모델·프롬프트를 고친다(사용자 결정, 2026-11-02).
  - **API 비용:** 공고 한 건의 본문을 1만 토큰, 출력을 1천 토큰으로 가정하면 `claude-haiku-5-5`($0.10 / $0.50 per 1M 토큰, 10만 토큰 이하 요청 기준)로 건당 약 $0.0015다. 첫 실행은 쌓인 공고 수백 건, 그 뒤로는 새 공고와 바뀐 공고만 부른다. 첫 실행에서 실제 토큰과 비용을 기록한다.
  - **파일 변환:** HWP 별표의 금리·한도 표는 텍스트로 바꾸면 구조가 흐트러질 수 있다. 인용 검증은 바꾼 텍스트를 기준으로 하므로 그대로 동작한다. 변환 라이브러리가 새 HWP 버전을 못 읽으면 그 공고는 "읽지 못함"이 된다.
  - **민감한 입력:** 대상 한정의 장애 여부는 개인정보보호법상 민감정보(건강)에 해당할 수 있다. 선택 입력으로 두고, 맞춰 보기에만 쓰며, AI에는 보내지 않는다(AI에는 공고 본문만 보낸다). 계획을 지우면 함께 지워진다.
  - **외부 전송:** 공고 본문(공개 문서)을 Anthropic API로 보낸다. 사용자 데이터는 보내지 않는다. 맞춰 보기는 서버에서 저장한 결과로만 한다.
  - **기능 제거:** 대출 가정 적용이 없어진다. 지금 적용 가능한 상품이 0건이라 실제로 잃는 것은 없다.
- **migration·호환성:**
  - 새 테이블을 더한다. 기존 자금 테이블과 릴리스는 지우지 않는다.
  - 기존 대출 가정 스냅샷은 그대로 읽힌다. 과거 `plan_results`는 다시 계산하지 않는다.
  - 계획의 자금 조건(`plans.fundingProfileJson`)은 사업자등록 여부·개업 연월·자치구·나이·대상 한정으로 바뀐다. 기존 값의 사업 단계와 자치구는 옮기고 업종·용도는 버린다(§4가 자금 조건에 자치구를 두므로 자치구도 옮긴다, 사용자 결정 2026-11-03).
- **운영·보안·데이터 영향:**
  - 새 비밀값 `ANTHROPIC_API_KEY`가 생긴다. 웹 서버에는 필요 없고 적재 명령에만 필요하다.
  - 소진공 공지 본문 전체를 저장해도 되는지 담당자 허용 범위(출처 표시 조건, ADR 0006 Context)를 다시 확인한다.

## Validation

- **단위 테스트(AI 응답 fixture 사용, 실제 호출 없음):**
  - PDF·HWP·HWPX fixture에서 텍스트가 뽑힌다. 뽑지 못한 파일은 건너뛰고, 읽을 파일이 없으면 "읽지 못함"이다.
  - 인용이 상품 이름과 본문 어디에도 없으면 그 값은 "읽지 못함"이다.
  - "언급 없음"은 맞음이나 안 맞음이 되지 않고 확인 필요다.
  - 같은 본문·프롬프트·모델이면 AI를 다시 부르지 않는다.
  - AI 호출이 실패하면 "읽지 못함"이고 출처 동기화는 성공이다.
  - 웹 요청 경로는 AI 클라이언트를 import하지 않는다.
- **맞춰 보기 테스트:** 사업자등록 여부, 개업 연월, 자치구, 나이, 대상 한정 조합별로 맞음·안 맞음·확인 필요가 기대대로 나온다.
- **호환성:** 기존 대출 가정 스냅샷 fixture가 계획 화면과 결과에서 그대로 읽힌다.
- **운영자 확인:** 첫 실행 뒤 운영자가 추출 결과를 원문과 대조해 보고, 오독이 많으면 모델·프롬프트를 고친다. 프롬프트를 바꾸면 버전을 올려 다시 추출한다.
