# ADR 0008: 상권 생존점수와 재무 계획 연결

- Status: Accepted
- Date: 2026-10-31
- Owners: Minseok Kang
- Related issue/PR: 작업 요청서 "상권 생존점수"
- Supersedes: 없음. [PRODUCT.md](../PRODUCT.md) 제외 범위의 "예측 ML, 종합 점수", AGENTS.md §3의 3번·5번, [ADR 0002](0002-provisional-market-sales.md) 결정 2의 "계산 결과(`plan_results`)에 저장하지 않는다"와 "사용자 가정에 자동으로 입력하지 않는다", [ADR 0003](0003-seoul-market-open-api.md) 결정 2의 기본 범위를 아래 범위에서만 개정한다.
- 개정: 2026-11-25, 모델 정의를 v4로 바꾼다(사용자 결정: AUC 기준 0.6은 그대로 두고 모델을 개선). 요식업 업종을 부분 통합으로 함께 학습하고 변수를 14개로 늘렸다. §1의 점수 내는 업종, §2, §3, Consequences를 고쳤다.
- 개정: 2026-11-24, §5에 계획 제목과 [자금 후보 보기]의 자치구 채우기를 적었다. 두 채우기는 이 ADR과 같은 PR(#44)로 병합된 코드에 이미 있었으나 처음 문구에서 빠졌다. 결정을 바꾼 것이 아니라 기록을 코드에 맞춘 것이다(#49를 대신한다).

## Context

예비 창업자는 상권을 본 뒤 "이 자리에서 이 업종이 버틸 만한가"를 판단하고 그 판단을 재무 계획으로 가져가야 한다. 지금까지는 `/markets`에서 `/`로 넘어가는 값이 없었고, 재무 계획의 월매출(`monthlyRevenue`)은 사용자가 직접 입력했다.

데이터 사실(2026-10-31 확인):

- 서울 열린데이터광장 API는 추정매출을 2021년 1분기부터 2026년 2분기까지 제공한다. 2020년 4분기는 0행, 2026년 3분기는 아직 없다.
- 2021~2023년 분기의 한식·커피 상권 코드는 모두 현재 영역(`TbgisTrdarRelm`) 1,650개 안에 있다. 서울시가 과거 분기도 현재 공간 단위로 다시 제공하므로 코드 대응표가 필요 없다. 22분기 동안 한식 1,553곳, 커피 1,433곳이 빠짐없이 이어진다.
- 기존 기본 적재 범위(2024년 1분기~)는 10분기라, 1년 전(t−4)과 1년 뒤(t+4)가 모두 필요한 기준분기가 2개뿐이다.
- 상권은 모두 자치구 코드를 가진다(25개 구).
- 일부 상권은 점포당 매출이 극단적이다. 예: 삼성중앙역 5번 한식은 분기 원값 약 90억 원, 점포 7~8개로 점포당 월매출(잠정)이 약 12.9억 원이다(업종 평균 약 6,100만 원). 결제 1건당 약 13.7만 원으로 법인·단체 수요로 보이며, 원자료 오류로 단정할 근거는 없다.

요청서 원안(1차 변수 3개)으로 학습한 결과는 테스트 AUC가 한식 0.580, 커피 0.556으로 기준(0.6)에 못 미쳤고, 공개 폐업률만 쓴 기준선(한식 0.574)과도 차이가 거의 없었다. 결과는 [학습 리포트](../../app/models/market-score/market-score-v3-20262.report.md)의 비교 표에 남아 있다.

## Decision

### 1. 범위

- 상권 × 업종 × 기준분기 단위의 **상권 생존점수** 하나만 제품 범위에 넣는다. 다른 예측 모델·종합 점수는 계속 제외한다.
- 점수는 "이 상권의 같은 업종 점포들의 향후 1년 폐업률이 서울 중간 수준보다 낮을 가능성"이다. 개별 점포의 생존 확률이나 개인 예상매출로 표시하지 않는다.
- 학습 대상은 한식(`CS100001`)과 커피·음료(`CS100010`)다. [ADR 0010](0010-food-service-industry-scope.md)이 요식업 업종 열 개로 넓혔고, 점수는 그중 열린 업종에만 낸다. **테스트 AUC가 0.6 미만인 업종은 점수를 내지 않고 "미지원 업종"으로 응답한다.** 모델 정의 v4(2026년 2분기)에서 점수를 내는 업종은 한식·중식·패스트푸드점·치킨전문점·분식전문점·호프-간이주점이고, 일식·양식·제과점·커피-음료는 미지원이다.
- 상권 적재 기본 시작 분기를 2021년 1분기로 바꾼다(API가 제공하는 첫 분기). `--from`·`--to`는 그대로 둔다.

### 2. 모델 (`market-score-def-v4`)

- 요식업 업종 열 개를 **부분 통합 로지스틱 회귀**로 함께 학습한다. 업종마다 절편을 두고, 계수는 공통 계수 + 업종 편차이며 편차에 L2 벌점(`DEVIATION_PENALTY` 300)을 준다. 표본이 적은 업종일수록 공통 계수를 따른다. 계수 파일에는 업종마다 절편·계수(공통 + 편차)·표준화 값을 풀어 저장하므로 점수 계산과 API는 v3와 같다. 업종별 표준오차는 벌점을 더한 정보행렬의 역행렬에서 Var(공통) + Var(편차) + 2·Cov로 구한다.
- v3(업종마다 따로 학습, 변수 6개)는 새 업종 여덟 개 중 패스트푸드점만 기준을 넘었다. 표본이 1,500~3,000행인 업종은 따로 학습하면 계수가 흔들리고, 같은 상권의 다른 업종 자료는 쓰지 않았다.
- 점포 수는 `유사_업종_점포_수`(ADR 0002의 분모), 폐업·개업 수는 `폐업_점포_수`·`개업_점포_수`, 매출은 `당월_매출_금액` 원값이다.
- 라벨: (t+1 ~ t+4 폐업 수 합) ÷ t 점포 수가 같은 업종·같은 기준분기 서울 상권 중앙값보다 크면 1이다. 미래 분기 값이 하나라도 없으면 0으로 바꾸지 않고 학습에서 뺀다.
- 변수(14개, 정의는 `dataset.ts`):
  - v3 변수 6개: 요청서 1차 변수 3개(매출 증감률, 점포당 매출, 점포 수 — 정의는 요청서와 같다), 직전 1년 폐업률(t−3~t 폐업 수 합 ÷ t−4 점포 수)·직전 1년 개업률(같은 방식)·프랜차이즈 비중(t 프랜차이즈 점포 수 ÷ t 점포 수).
  - 업종 변수 4개: 직전 2년 폐업률(t−7~t 폐업 수 합 ÷ t−8 점포 수), 점포 수 증감(log t ÷ t−4), 건당 매출(log 매출 ÷ 매출 건수), 상권 내 업종 비중(t 점포 수 ÷ 같은 상권 요식업 점포 수).
  - 상권 변수 4개: 같은 상권 요식업 업종 전체의 직전 1년 폐업률·개업률, 매출 증감률(log t ÷ t−4, 두 분기 모두 매출이 있는 업종끼리만), 점포 수(log). 그 분기 행이 있는 업종만 더하고, 행이 있는데 값이 없으면 계산하지 않는다.
  - 변수 목록은 설정(`ACTIVE_FEATURE_KEYS`)으로 분리한다.
- **선택 방법:** 학습 기준분기 10개 중 앞 6개로 학습하고 뒤 4개(2023년 3분기~2024년 2분기)를 검증 분기로 써서, 업종 평균 검증 AUC로 변수 묶음과 벌점을 골랐다. 테스트 분기는 고른 뒤 한 번만 봤다. 변수를 하나씩 뺐을 때 검증 AUC 평균이 0.001 넘게 떨어지지 않는 변수(2년 전 1년 폐업률, 수축 추정 폐업률)는 뺐고, 상권 유형(발달상권·전통시장) 표시 변수는 검증 AUC 평균을 0.0015 올렸지만 화면의 기여 변수 표시(값·업종 평균 비교)에 맞지 않아 뺐다. 실험 기록은 PR에 남긴다.
- 직전 2년 폐업률이 t−8 점포 수를 쓰므로, 자료 시작(2021년 1분기)에서 2년이 지나지 않은 2022년 기준분기 행은 학습에서 빠진다(`FEATURE_UNAVAILABLE`). 학습 행이 52,327에서 31,444로 줄고, 테스트 행과 최신 분기 점수 대상은 거의 그대로다(20,470 → 20,469).
- 업종별 학습셋 평균·표준편차로 표준화하고, **표준화 값은 학습과 점수 계산 모두 ±3에서 자른다.** 극단값 상권 하나가 점수를 좌우하지 않게 하려는 것이며 원값은 바꾸지 않는다.
- 제외: t 점포 수가 최소 점포 수(설정값, 기본 5) 미만이거나, t 또는 t−4 매출이 0·없음이거나, 변수 계산에 필요한 값이 없는 행. 학습과 화면 모두에서 뺀다.
- 분할: 기준분기는 2022년 1분기~2025년 2분기(14개)다. 마지막 4개(2024년 3분기~2025년 2분기)가 테스트, 나머지 10개가 학습이다.
- 학습은 오프라인 명령 `score:train`이 한다. IRLS를 TypeScript로 직접 구현하고 학습 라이브러리를 추가하지 않는다. 결과는 `app/models/market-score/<버전>.json`(계수·표준화 값·학습 기간·지표·상권 릴리스 키)과 같은 이름의 학습 리포트(`.report.md`)로 남기고 Git에 포함한다. 같은 버전 파일은 덮어쓰지 않는다.
- 점수 = round((1 − p) × 100), 기여도 = −β × z. 등급은 요청서의 초기 구간(AAA 90 이상 … D 30 미만)을 그대로 쓰고 계수 파일에 함께 저장한다.

### 3. 기준선 비교

같은 학습·테스트 행으로 기준선(직전 1년 폐업률), 요청서 1차 모델, 결합 모델(기준선 + 1차 변수), 업종별 v3 모델을 업종마다 따로 학습하고 채택 모델(부분 통합)과 함께, 같은 점수 변환·등급 구간으로 업종·모델별 테스트 AUC, KS, 등급별 상권 수·고폐업 비율·실제 향후 1년 폐업률 평균을 리포트에 낸다. 상권변화지표를 적재하면 4단계 지표 더미 변수로 된 기준선 2를 더한다.

### 4. 점수 적재와 API

- `score:build`가 계수 파일과 ACTIVE 상권 릴리스로 최신 기준분기의 모든 상권 점수를 계산해 새 점수 릴리스로 저장한다. `PENDING → ACTIVE` 검증을 거치고 실패하면 기존 ACTIVE를 유지한다(AGENTS.md §3-9). 점수를 내지 않은 상권도 이유(표본 부족·데이터 없음)와 함께 행으로 남긴다.
- 점수 릴리스는 모델 버전, 계수 파일 SHA-256과 내용, 상권 릴리스 키, 기준분기, 업종별 분포·변수 평균을 보존한다.
- 공개 API(`/api/markets/score`, 로그인 불필요)는 ACTIVE 점수 릴리스만 읽는다. 웹 요청 중에 학습하거나 외부 데이터를 가져오지 않는다. 상태 4가지(정상·표본 부족·미지원 업종·데이터 없음)는 200으로 구분한다.

### 5. 재무 계획 연결

- 사용자가 `/markets`에서 [이 상권으로 재무 계획 시작] 또는 [자금 후보 보기]를 누른 경우에만 값을 미리 채운다. 자동으로 채우는 경로는 이 둘뿐이다.
- [이 상권으로 재무 계획 시작]이 채우는 곳: 계획 제목(`{상권} {업종} 계획`), 계획의 자금 조건 자치구 입력란, 재무 입력의 월매출. 사업 조건(위치·업종·면적·층·상가 유형)은 일부만 채우면 저장이 막히므로 채우지 않는다.
  - [ADR 0009](0009-funding-ai-condition-extraction.md) §6으로 자금 조건 업종 채우기를 없앴다. 자금 조건에 업종 입력이 없어졌기 때문이다.
- [자금 후보 보기]가 채우는 곳: `/funding`의 자치구 조회 입력란이 비어 있을 때만 그 상권의 자치구. 조회 조건이라 저장되지 않는다. `/funding`은 상권 참조를 URL에서 지우지 않으므로 그 URL을 다시 열면 비어 있는 자치구를 다시 채운다.
- 자치구는 사용자가 고른 상권의 식별값이고 계획 제목은 사용자가 고칠 수 있는 이름이다. 둘 다 재무 가정이 아니므로 AGENTS.md §3의 3번과 충돌하지 않는다.
- 월매출 기본값 = t−3~t 매출 원값 합 ÷ 같은 기간 점포 수 합. ADR 0002의 잠정 점포당 월매출을 4분기로 평균한 값이다. 요청서의 ÷12 식은 원값을 분기 합계로 본 해석이라 쓰지 않는다.
- 입력란 위에 출처("{상권명} {업종} 점포당 평균 기준 · 등급 {등급}")와 "잠정", 원값 합과 점포 수 합을 표시한다. 사용자가 값을 고칠 수 있다. 기본값이 같은 업종 점수 낸 상권의 하위·상위 1% 범위를 벗어나면 "개인 점포 매출과 크게 다를 수 있다"는 경고를 붙인다. 예: 삼성중앙역 5번 한식 약 12.9억 원(상위), 청량리수산시장 한식 79,150원(하위).
- 화면은 상권 참조(점수 릴리스 키·상권·업종)만 URL로 넘긴다. 로그인 화면에서는 참조를 URL에 그대로 두고, 로그인한 뒤 계획 화면이 참조를 읽자마자 URL에서 지워 한 번만 쓴다. 그래서 점수 API가 실패해도 같은 오류를 다시 띄우지 않고, 저장하지 않고 떠났다가 일반 링크로 돌아오거나 새로고침하면 다시 채우지 않는다. 계획을 만들 때 서버가 그 점수 릴리스에서 등급·점수·월매출 기본값을 다시 읽어 `plans.marketScoreJson`에 재무 입력과 분리해 저장한다. 다시 볼 때는 다시 계산하지 않고 저장 당시 값을 보여 준다. 계획 수정은 이 스냅샷을 바꾸지 않는다.
- 채운 월매출은 사용자의 재무 입력(`inputJson.monthlyRevenue`)이다. 고치지 않고 계산하면 그 값이 계산 결과(`plan_results.inputSnapshot`)에 사용자 가정으로 남는다. 출처와 잠정 여부는 계획의 `marketScoreJson`에 남고, 결과에는 따로 적지 않는다. [상권 연결 해제]를 누른 뒤 저장하면 스냅샷을 남기지 않는다. 폼에 남은 값은 출처 없는 사용자 입력이 되며, 해제 안내 문구가 직접 고칠 수 있다고 알린다. 이 경로 밖의 잠정 값(상권 화면의 점포당 월매출 등)은 계속 계산 결과에 저장하지 않는다.
- 등급은 `/funding` 위쪽에 표시한다. 자금 후보 판정에는 쓰지 않는다.

## Alternatives considered

- **2024년 이후 10분기로 반년 라벨:** 지금 데이터로 학습할 수 있지만 요청서의 1년 폐업률과 정의가 달라진다. 2021년 자료가 같은 코드 체계로 있으므로 기각한다.
- **요청서 1차 변수 3개만 사용:** 테스트 AUC가 두 업종 모두 0.6 미만이고 기준선과 차이가 없다. 기각한다.
- **AUC 기준을 낮춰 커피도 제공:** 근거 없는 정밀도를 만든다. 기각한다.
- **표준화 값을 자르지 않음:** 점포당 매출이 극단적인 상권 몇 곳이 최상위 점수를 독차지한다. 기각한다.
- **월매출을 채우지 않고 참고값만 표시:** 상권 → 재무 계획 흐름을 잇는다는 목적을 이루지 못한다. 기각한다.
- **요청서의 ÷12 식:** ADR 0002가 기각한 해석이다. 따르지 않는다.
- **업종마다 v3와 v4 중 테스트 AUC가 높은 쪽을 씀(v4 개정):** 같은 표본에서 양식은 v3 업종별 모델(0.601)이 v4(0.574)보다 높다. 업종마다 테스트셋을 보고 모델을 고르는 것은 테스트셋 과적합이라 하지 않고, 검증 분기로 고른 한 방식을 모든 업종에 쓴다.
- **모든 업종 점수를 위해 AUC 기준을 낮춤(v4 개정):** 위의 "커피도 제공"과 같은 이유로 기각한다(사용자 결정 2026-11-25).
- **학습셋을 보고 상위 등급 경계를 옮김:** 학습셋 기준으로 옮겨도 테스트셋의 상위 구간 순서가 바뀌지 않았다. 테스트셋에 맞춰 옮기는 것은 과적합이라 하지 않고, 원안 구간을 유지한다.

## Consequences

- 장점: 상권 → 재무 계획 → 자금 후보 흐름이 이어진다. 점수의 근거(계수·표본·AUC·기준선 비교)를 화면과 파일로 재현할 수 있다.
- 비용·위험:
  - 변별력이 약하다(v3 한식 테스트 AUC 0.625, KS 0.196). 70점 이상 구간에서는 고폐업 비율이 더 내려가지 않는다. 화면과 리포트에 모델 정보와 한계를 함께 표시한다.
  - v4는 점수를 내는 업종을 2개에서 6개로 늘리지만, 새로 낸 업종의 테스트 AUC는 0.61~0.63으로 기준을 조금 넘는 정도다. 일식·양식·제과점·커피-음료는 이 자료로는 기준을 넘지 못했다(제과점 0.53).
  - 직전 1년 폐업률은 직전 2년 폐업률과 상관이 커서(r 약 0.79) 열 업종 모두 계수 부호가 예상과 반대다(폐업률이 높으면 점수를 조금 올림). 규칙대로 빼지 않고 리포트에 표시한다. 기여 변수 상위 4개에 들면 화면에 "높음 → 점수 올림"으로 보일 수 있다.
  - 상권 변수는 같은 상권의 요식업 업종 전체 자료를 쓴다. 학습과 점수 계산이 같은 업종 목록(`INDUSTRY_CODES`)을 읽어야 값이 같다.
  - 마지막 학습 기준분기와 첫 테스트 기준분기의 라벨 기간이 3분기 겹친다. 테스트 AUC가 실제보다 조금 높을 수 있다.
  - ADR 0002의 해석이 틀리면 월매출 기본값이 약 3배 달라진다. "잠정"·원값 표시와 사용자 수정 가능으로 피해를 제한한다.
  - 상권 적재가 22분기로 늘어 한 번에 약 5분이 걸린다.
- migration·호환성: `plans.marketScoreJson`(nullable)과 `market_score_releases`·`market_scores` 테이블을 추가한다. 기존 계획과 결과는 바꾸지 않는다. `/api/markets/summary`·`report`의 가용 분기가 2021년 1분기부터로 늘어난다.
- 운영·보안·데이터 영향: 점수 API는 로그인 없이 공개한다. 계수 파일은 공개 데이터만으로 만든다. 운영자는 상권 적재 뒤 `score:build`를 실행해야 점수가 갱신된다.

## Validation

- 학습 리포트: 업종별 학습·테스트 기간, 표본 수, 라벨 1 비율, 계수·표준오차·p값, 상관 0.7 이상 변수 쌍, 테스트 AUC, 10점 구간 분포, 등급별 상권 수, 테스트셋 등급별 실제 고폐업 비율, 기준선 비교.
- 등급 단조성은 모든 등급 기준과, 테스트 표본 30건 미만 등급을 뺀 기준을 함께 적는다. 모델 정의 v4(2026년 2분기)에서 점수를 내는 여섯 업종 모두 BBB→D는 고폐업 비율이 올라간다. 30건 이상 기준으로 중식·패스트푸드·분식은 모든 등급에서 단조이고, 한식(AA 37.3% > A 29.3%)·치킨(A 37.1% > BBB 33.2%)·호프-간이주점(A 38.5% > BBB 36.4%)은 상위 등급에서 순서가 뒤집힌다. v3 한식은 30건 이상 기준으로 A→D가 단조였다.
- 중단 조건: 업종 모델의 테스트 AUC가 0.6 미만이면 그 업종은 점수를 내지 않는다. 예상과 부호가 다른 변수는 표시만 하고 빼지 않는다.
- 단위 테스트: 변수·라벨 계산, 점수·등급 변환, 기여도 정렬, ±3 자르기, 예외 상태 4가지, 월매출 기본값 산식, 기준선 비교 표본, 계획 저장 경계.
- DB 테스트: 점수 릴리스 활성화·재실행·실패 시 기존 ACTIVE 유지, 점수 API 상태, 계획 스냅샷.
- E2E(desktop·mobile): `/markets` 상권 선택 → 점수 표시 → [재무 계획 시작] → 회원가입 → 값 채워짐 → 저장 → 다시 보기에서 등급 유지 → `/funding` 등급 표시.
