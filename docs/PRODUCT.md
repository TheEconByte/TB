# TrendBench 제품 기준

이 문서는 제품 의도·원칙·범위와 현재 제공 기능을 담는다. 기능을 추가·변경하는 PR은 [현재 제공 기능](#현재-제공-기능)을 같은 PR에서 고친다. 범위를 바꾸려면 [ADR](decisions/README.md)을 먼저 작성한다.

## 대상과 해결하려는 문제

서울에서 음식점·카페 창업을 준비하는 예비 창업자는 공개 상권 통계, 점포 경쟁, 임대·시설비, 정책자금 조건, 자신의 매출 가정을 서로 다른 출처에서 확인해야 한다. TrendBench는 이 정보를 같은 화면에 모으되 관측 사실과 사용자 가정을 섞지 않고, 다음 질문에 답하도록 돕는다.

- 어디에서 어떤 업종을 계획하는가?
- 해당 상권과 업종에서 공개적으로 관측된 사실은 무엇인가?
- 내가 입력한 가정으로 얼마가 필요하고 매월 감당 가능한가?
- 현재 검토할 수 있는 자금 후보와 추가 확인 조건은 무엇인가?
- 어떤 데이터가 없거나 확정되지 않았는가?

## 사용자 흐름

| 단계 | 사용자 입력 | 제품 출력 |
|---|---|---|
| 사업 조건 | 자치구·상위/세부 업종·면적·층·상가 유형 | 분석 범위와 저장된 사업 프로필 |
| 상권 탐색 | 자치구·상권·업종 | 서울시 상위 업종 관측값, 소진공 세부 업종 경쟁 점포, 출처·기준일 |
| 재무 계획 | 비용·자기자금·월매출·고정비·변동비·가정 대출 | 필요자금·부족자금·운영수지·상환 일정·시나리오 |
| 자금 후보 | 사업단계·지역·업종·용도 | 후보·미충족·미확인·종료·등록 이후 검토 사유 |
| 저장·비교 | 계획명과 수정한 가정 | 초안·불변 결과·향후 결과 비교 |

상권 탐색(`/markets`)은 공개, 개인 계획 저장·계산(`/`)과 자금 후보(`/funding`)는 로그인 후 제공한다. 관측 데이터가 부족해도 사용자는 자신의 가정으로 재무계획을 계속할 수 있다.

## 제품 원칙

1. **관측과 가정을 분리한다.** 서울시 매출은 시장 관측값이고 개인 예상매출이 아니다.
2. **집계 범위를 숨기지 않는다.** 매출·고객은 서울시 상위 업종, 경쟁 점포는 소진공 세부 업종 기준이다.
3. **모르면 모른다고 표시한다.** `null`, `UNKNOWN`, 자료 부족, 현재 신청 가능 0건은 서로 다른 상태다.
4. **재현 가능한 결과를 남긴다.** 입력·계산 버전·데이터 릴리스·상품 버전·checksum을 저장한다.
5. **승인처럼 말하지 않는다.** 자금 후보는 검토 시작점이며 대출·지원 승인이나 신용 판단이 아니다.
6. **사용자가 적용을 결정한다.** 외부 임대료·프랜차이즈·대출 조건은 명시적 선택 없이 재무계획에 반영하지 않는다.
7. **근거 없는 정밀도를 만들지 않는다.** 시간 단위·분모·공식 조건이 불확실하면 계산을 비활성화하거나, 근거가 있는 잠정 해석임을 표시한다([ADR 0002](decisions/0002-demo-sprint-scope.md)).

## 현재 제공 기능

| 영역 | 제공 범위 | 기준 |
|---|---|---|
| 사업 조건 입력 | 자치구, 서울시 상위 업종, 소진공 세부 업종, 면적, 층, 상가 유형 | 계획의 `businessProfileJson`에 재무 입력과 분리 저장 |
| 상권 분석 | 상권별 매출 금액·건수, 점포·개폐업, 요일·시간대·성별·연령대 구성 | 서울시 상권분석서비스 상위 업종 관측값, 2024년 1분기~2025년 4분기 |
| 경쟁 점포 | 자치구·소진공 세부 업종별 점포 수와 최대 50개 목록 | 소진공 상가(상권)정보 스냅샷 |
| 재무 계획 | 초기 비용, 자기자금, 매출·비용 가정, 부족자금, 운영수지, 손익 기준 | 사용자가 입력한 가정만 계산 |
| 인증·저장 | 회원가입·로그인, 계획 CRUD, revision 충돌, 소유자 권한 | Better Auth + PostgreSQL |
| 계산 결과 | 서버 재계산, 입력·계산 버전과 출처를 보존한 불변 결과 | 기존 결과를 수정하거나 자동 재계산하지 않음 |
| 자금 후보 | 사업 단계·지역·업종·용도에 따른 규칙 기반 후보 분류 | 사람이 검수한 카탈로그만 사용. 현재 카탈로그는 검수자 미지정으로 적재 전 |
| 대출 가정 적용 | 확정 조건을 갖춘 현재 후보를 사용자가 명시적으로 선택 | 미확정·비대출 상품은 적용 불가 사유 표시 |

상위 업종은 한식(`CS100001`)과 커피·음료(`CS100010`)만 노출한다. 데이터별 적재 기준과 건수는 [market.md](domains/market.md), [business-directory.md](domains/business-directory.md), [funding.md](domains/funding.md)에 있다.

## 제외·보류 범위

- 세부 업종 매출·고객·배달 분석: 재사용 가능한 공식 출처가 없다.
- 확정된 매출 월 환산과 점포당 매출: 원천의 시간 단위와 분모가 공식 확정되지 않았다. 확정 전에는 [ADR 0002](decisions/0002-demo-sprint-scope.md)의 잠정 값만 제공한다.
- 임대료·프랜차이즈 비교: 검수된 스냅샷이 없어 API가 `503 DATASET_UNAVAILABLE`로 실패한다.
- POS·매출 파일 업로드·기존 점주 운영 분석
- 예측 ML, 종합 점수, 신용 판단, 자동 승인, 최적 조달 조합
- 주소 자동 상권 매핑, 지도, 전국 확대, 관리자 대시보드
- 자동 공고 해석·무검수 운영 반영

새 기능은 “데이터를 확보할 수 있는가, 의미가 맞는가, 지속 검수할 책임자가 있는가”를 모두 통과한 뒤 범위에 넣는다. 남은 결정과 작업은 GitHub Issue와 Milestone에서 관리한다.

초기 설계 과정은 [history/12_Simplified_MVP_Technical_Plan.md](history/12_Simplified_MVP_Technical_Plan.md), 당시 데이터 검증은 [history/13_Data_API_Feasibility_Verification.md](history/13_Data_API_Feasibility_Verification.md)에 남아 있지만 현재 범위보다 우선하지 않는다.
